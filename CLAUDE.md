# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Hit them all!" is a top-down 2D action game in C# on .NET 10 using Raylib-cs 8.1 (`MyGame.csproj`, assembly `HitThemAll`). All source files sit flat in the repo root, with no namespaces and a top-level-statements entry point (`Program.cs`). There is no test project.

## Commands

```sh
dotnet build                                          # debug build (console attached, so Console.WriteLine output is visible)
dotnet run                                            # build and play
dotnet publish -c Release -r win-x64 -o publish       # shipping build: self-contained single-file WinExe
```

Release publishing must stay untrimmed (`PublishTrimmed=false`) because `SaveData` uses reflection-based System.Text.Json.

Stage backgrounds are generated by Python scripts (requires Pillow):

```sh
python tools/stages/make_stages.py                 # every stage
python tools/stages/make_stages.py forest_glade    # just the named ones
python tools/stages/make_stages.py --tmx ...       # also regenerate existing .tmx (overwrites hand edits made in Tiled)
```

Previews and a contact sheet go to `tools/stages/out/` (gitignored). The script warns when open tiles can't be reached from the spawn.

Enemy art for every `EnemyLook` except the Grunt's `Sprite` is generated the same way, in the maps' style:

```sh
python tools/enemies/make_enemies.py               # every look
python tools/enemies/make_enemies.py imp wisp      # just the named ones
```

It writes `textures/enemies/{look}_idle.png` (an 8-frame loop) and `{look}_death.png` (6 frames, played once). Frames are 256 px, which is 128 world units at 2x, with the body centred, and all art faces right (`Enemy` mirrors it to face the player).

It also writes an attack sheet for each kind of attack a look has, `{look}_melee.png` and/or `{look}_ranged.png`. A sheet has three rows (side, down, up) of 8 frames: 5 of windup, the frame where the blow lands or the shot leaves, and 2 of follow-through. Each sheet is cropped to fit its own swings. Its frames stay square and centred on the body, and the game sizes them from their pixel size. Ranged windups are the same in every row, so the game can switch rows while it follows the player.

Previews go to `tools/enemies/out/` (gitignored): `contact_sheet.png` has the hit boxes drawn on, `on_maps.png` shows every look on every stage, and `attacks.png` shows every attack sheet with the swing reach and the muzzles drawn on. The generator's `LOOKS` table mirrors `EnemyIcons.BodyScale`/`HitExtent`/`TopExtent`/`Muzzle`, so change both together. The script warns when a shot's actual release point drifts from `LOOKS`.

## Architecture

**Frame loop** (`Program.cs`): `game.Update(dt)`, then `World.FitCamera` (called every frame because the window is resizable and starts borderless-fullscreen), then `game.DrawWorld()` inside `BeginMode2D` (world space), optionally wrapped in `BlurEffect` while paused, then `game.DrawUi()` in screen space. HUD and menus must position themselves with `Screen.Width/Height` (the actual window), never `World.Width/Height`.

**Startup order matters** (`Program.cs`): `InitWindow` comes first, then `Assets.Load()` (raylib needs a GL context to upload textures), then `StageMap.Load(...)`, and only then `new Game()`. The order is required because `Player`'s field initializer reads `CollisionMap.PlayerSpawn`.

**Asset paths are relative.** `Program.cs` sets `CurrentDirectory` to the exe folder, and the csproj copies `textures/**`, `sounds/**`, `tile.png` and `assets/dungeon.tmx` to the output directory. A new asset folder needs a matching `<None ... CopyToOutputDirectory>` entry. Anything loaded in `Assets.Load()` needs a matching unload in `Assets.Unload()`. `Assets.Load` loads `textures/mainmenu.png`, which doesn't exist; raylib only logs a warning, and the main menu draws `welcome.png` instead.

**Much of the state is global and static:** `World`, `CameraFocus`, `CollisionMap`, `StageMap`, `Assets`, `FloatingNumbers`, `Game.pickups`/`Game.loot`, `Enemy.AggroEnabled` and `Player.GodMode`. New static state needs an explicit reset in `Game.StartRound`/`ContinueRound`/`BeginStage`.

**`Game.cs` is the central coordinator.** It holds a `GameState` state machine (Welcome → MainMenu → Playing ⇄ Paused → GameOver) and owns the player, enemies, pickups, powers, banners, HUD drawing and the multi-phase ultimate sequence (`UltimatePhase`: Targeting freezes the world and lets the player click an enemy; ZoomIn uses `CameraFocus`; then Attack teleports the player beside the target and swings).

**Combat resolution is split across files:**
- `Game.UpdatePlaying` applies the player's swing damage, but only on the frame where `Player.SwingLanded` is true (the impact frame of the axe animation), not for the whole attack.
- `Game.UpdatePlaying` also resolves enemy attacks by calling methods on `Enemy`: `ConsumeProjectileHit`/`BlockProjectile` and `BlockMelee`/`ConsumeMeleeHit`. A parry (E) that blocks an attack is worth 1 point.
- An enemy makes one attack at a time (`Enemy.UpdateAttack`): a windup, then the moment the blow lands or the shot leaves, then a follow-through (`AttackRecovery`) during which it stands still.
  - A melee swing fixes its aim on the player when the windup starts. It hits a `MeleeArc` (120°) wedge out to `MeleeRadius`, and the red telegraph on the ground shows that wedge.
  - A ranged shot follows the player through its windup (`EnemyIcons.CastWindup`) and leaves from the weapon (`EnemyIcons.Muzzle`). It falls back to the body centre when the player is closer than the muzzle or a wall is in the way.
  - The aim's dominant axis picks the attack sheet's row.
- Every finished swing spawns an `ElementalTrail`. Its damage is applied inside `Player.Update`, not in `Game`.
- Living enemies' bounds are passed to `Player.Update` as solid obstacles.

**Controls** are read in both `Player.cs` and `Game.cs`: WASD to move, Shift to run, left mouse for a light attack, right mouse for a heavy attack, E to parry, F to use the ultimate once the meter is full, and number keys for powers (1 is Slow Time). The control scheme in `TODO.md` is outdated.

**Time scaling:** the player and `Power` timers tick on real `dt`. Enemies, projectiles, popups, pickups and spawning tick on `worldDt = dt * TimeScale`, which slows while `SlowTimePower` is active. New world-side systems should use `worldDt`.

**Stages and content are data-driven** in `Stages.cs`:
- `Enemies` holds `EnemyDef` records (stats, `EnemyAttackType`, `EnemyLook`). `EnemyDef.Spawn()` builds an `Enemy`.
- `Stages.All` is the ordered list of `StageDef`s (map name, `MaxAtOnce`, roster, loot table). `Roster(...)` interleaves the enemy groups evenly.
- Loot tables use `Drops.cs` (`DropDef` / `LootChance`). `Game.DropLoot` is static so dying enemies can call it.
- Enemy looks other than `Sprite` are drawn from the generated strips in `textures/enemies/` (loaded into `Assets.EnemyArt`) by `EnemyIcons.cs`, which also supplies their size and hit-box extents.

**Maps:** each map is a pair of files, `textures/stages/{name}.png` (the floor image) and `{name}.tmx` (a Tiled file). `StageMap.Load` switches maps only when the name changes. It returns false when the map is unchanged, and in that case the player keeps their position between stages. `CollisionMap.Load` parses the TMX:
- The TMX tile grid sets `World.Width/Height`.
- Rect objects in an object layer named `Pits` block walking but not shots or line of sight. Rect objects in any other layer are full walls. Polygons and ellipses are ignored.
- Point objects named `PlayerSpawn` / `EnemySpawn` (spaces and case ignored) are the spawn points.

The Python generator in `tools/stages/` produces both files. It keeps every edge on a 32px tile grid (`World.Tile`) and never overwrites an existing `.tmx` unless given `--tmx`. The stage order in `make_stages.py` `STAGES` mirrors `Maps` in `Stages.cs`.

**Save/checkpoint** (`SaveData.cs`, `Game.SaveProgress`): JSON saved at `%LocalAppData%/HitThemAll/savegame.json`.
- The saved stage number only moves forward when a stage is cleared (`AdvanceStage`). Continue always restarts that stage from its first enemy.
- Pause → Main Menu also saves, and writes the current score, HP and ultimate meter into the checkpoint.
- Game over does not save.
- The Continue option is enabled when `checkpoint.Score > 0`; `SaveData.HasProgress` exists but nothing uses it.

**Enemy status effects** (`StatusEffect.cs`, `EnemyBodyEffect.cs`): Burning, Frozen, Shocked, Poisoned and Stunned. `Enemy.ApplyStatus(status, seconds, dotDamage?, speed?)` refreshes a status and never shortens it, `HasStatus` checks one, and `ClearStatuses` ends all of them. Nothing triggers them in play yet. `Enemy.ActionSpeed` scales the clock for movement, attack cooldowns and the melee windup. It is the slowest `speed` among the active statuses. `speed` sets it per call; otherwise `Enemy.DefaultSpeed` applies (Stunned 0, Frozen 0.5, Poisoned and Shocked 0.75, Burning 1). At 0 (a stun, or a full freeze with `speed: 0`), the enemy also cancels its windup and stops turning. Projectiles already fired keep full speed. Damage over time is part of a status, not a status of its own. Each status has its own damage per tick, dealt once a second through `ReceiveDamage` (crimson numbers; a kill counts as a normal kill). `dotDamage` sets it per call. Without it, the status's default from `Enemy.DefaultDot` applies: `BurningDot` and `PoisonedDot` are 5, and the others are 0. Different statuses tick separately, and ticks pause during the ultimate cinematic. Their timers tick on `worldDt`. `EnemyBodyEffect` is the single shader for the enemy body: it draws every active status look plus the hit flash in one pass, because raylib allows only one active shader. A new status needs an enum value, a bump to `StatusEffects.Count`, an entry in `StatusUniforms` and a uniform with its look in the fragment shader.

**Powers** (`Power.cs`): an abstract `Power` class with a number-key toggle, a duration and a cooldown. To add a power, subclass it and add the instance to `Game.Powers`. The HUD shows `PowerSlots` (3) slots.

## Debug keys (in game)

F1 shows collision walls, pits and spawns. F2 shows hit boxes. F3 toggles enemy aggro. F4 toggles god mode. F5 puts living enemies under the next status in the cycle for 5 s, and Shift+F5 applies all of them at once. Shift+F1 shows the list of debug keys. F11 toggles borderless fullscreen. Esc pauses the game; it does not quit.
